# Flame1Down - 1（试验版）

一款类宝可梦的精灵对战网页游戏。精灵来自手绘图鉴，战斗方式参考赛尔号，带有账号、配队、图鉴和星际探索剧情。

## 怎么玩

把仓库下载到电脑（绿色 **Code** 按钮 → **Download ZIP**），解压后双击 `index.html`，用浏览器打开就能玩，不需要安装任何东西。

整个文件夹要保持原样：`index.html`、`css`、`js`、`images` 必须放在同一个目录里。

## 常见修改

### 改数值、改技能描述

直接在 `js/data/creatures.js` 或 `js/data/moves.js` 里找到对应的精灵或技能改数字。用编辑器的搜索功能（Mac 上 `Cmd + F`）搜精灵名或技能名最快。

### 新增一只精灵

1. 在 `js/data/creatures.js` 的 `SP` 列表里照着已有的格式加一项。`id` 用英文小写，例如 `fox`。
2. 技能如果是新的，在 `js/data/moves.js` 的 `M` 里加上。精灵的 `moves`、`hidden`、`def` 里写的技能名必须和 `M` 里的完全一致。
3. 把立绘放进 `images/sprites/`，文件名用 id，例如 `fox.png`。
4. 打开 `js/data/assets.js`，在 `SPRITES` 里加一行 `"fox": "images/sprites/fox.png",`。
5. 有进化前形态的话，图片放进 `images/pre_sprites/`，命名为 `fox_s1.png`、`fox_s2.png`，并在 `PRE_SPRITES` 里加对应的行。手绘原画同理，放 `lineart/`，登记在 `LINEART`。

只在账号系统里出现、不参加竞技对战的精灵，加在同一个文件里的 `EXTRA_SP`。

### 改剧情对话

剧本都在 `js/data/story.js`。每个地点是一个列表，一行是一句话，例如：

```js
{ s: 'v', on: [['p', 'l'], ['v', 'r']], t: '{name}！这边这边！' },
```

- `s`：说话人。`n` 是旁白，`p` 是玩家，其他代号见 `js/ui/game.js` 里的 `CAST`
- `t`：台词。`{name}` 会自动换成玩家的名字
- `on`：站在画面上的角色和位置（`l` 左，`r` 右）
- `bg`：切换背景，值是 `BG` 里的名字

新增一个剧情地点时，除了在 `story.js` 里加剧本，还要在 `js/ui/game.js` 的 `SITES` 里登记这个地点。

- `mons`：画面中间显示的精灵。`tw:精灵id` 是被瘴气污染的样子；`mon:精灵id:等级:标签` 是普通样子（例如 `mon:kaleo:15:？？？`）
- 精灵也能当说话人：`CAST` 里写 `spr: 精灵id`（`sprLv` 指定等级，决定显示哪个形态），例如卡罗 `kr`、卡莱 `kl`

### 主线章节

主线分成若干章节（`js/ui/game.js` 的 `CHAPTERS`）。一个章节的剧情全部读完，会额外发一份章节大奖（存档里记在 `chapters`，每个存档一次）；章节推出前就已经读完的，打开游戏时通过邮箱补发。还没写完的章节标 `wip: true`（未完待续），写完之前不算通关，写完后去掉它，已经读完的人会自动收到奖励。

| 章节 | 包含 | 章节大奖 |
|---|---|---|
| 序章 | 第一段～第四段（省实验中学 → 登上荆楚号） | 累积经验 5000 |
| 第一章 · 芙罗拉星（未完待续） | 第五段 降临芙罗拉、第六段 卡罗的不安、第七段 猎杀者…… | 茶室音乐「芙罗拉星」 |

**第六段读完后的主线任务「引出猎杀者」**：芙罗拉星丛林、草甸的野生精灵不会倒下，体力剩 1 点时逃走（战斗结果 `spared`，算击败，有经验），记作「假装击败」，攒满 5 只开放第七段（存档 `story.flora2.spare`，规则在 `game.js` 搜「引出猎杀者」，引擎在 `battle.js` 的 `faint()`）。

剧情道具（`game.js` 的 `KEY_ITEMS`）：精灵翻译器（第六段）、烟雾保护头盔（第七段），显示在储存箱的一般道具里，不能使用。道具图放在 `images/items/`，登记在 `assets.js` 的 `ITEM_IMG`（无人机只在剧情里出现）；剧本里写 `mons: 'item:图名:标签'` 就会在画面中间显示道具。

### 换图片

用同名文件直接覆盖 `images/` 里的旧图即可，代码不用改。如果新图的格式不同（比如 png 换成 webp），记得同步改 `js/data/assets.js` 里的文件名。

## 修改后怎么检查

1. 改完保存，在浏览器里刷新 `index.html`。
2. 如果页面空白或者点了没反应，按 `Cmd + Option + I` 打开开发者工具，看 **Console** 里的红色报错，一般会写出是哪个文件、第几行出了问题。最常见的原因是少了逗号或括号。

## 一起修改的约定

1. 动手改之前在群里说一声，改完提交了再说一声，尽量不要两个人同时改同一个文件。
2. 改之前先拉取仓库里的最新版本。
3. 提交时写清楚改了什么，例如"新增精灵：狐火"、"修复换精灵时血条不刷新"。

## 服务器（联网版）

游戏也部署在一台腾讯云轻量服务器上，用浏览器打开 `http://服务器IP` 就能玩，联网对战也走这台服务器。

```
server/
  server.js           服务器程序：发网页 + 在 /ws 上给联网对战传话
  accounts.js         账号与云存档（注册、登录、上传存档）
  pvp.js              联网对战的服务器裁判：切磋、平衡模式、竞技征召、争霸赛、精灵大乱斗由服务器结算每一回合（精灵资料见 js/engine/pvp.js）
  pve.js              单人对战（打电脑）由服务器结算：目前是先驱之塔（规则见 js/engine/pve.js），打完后服务器直接发奖励、推进层数
  claims.js           进账申报与钱包核对：一次性奖励只认一次，上传的存档里没申报的增加不认（试运行 / 正式两种模式）
  tx.js               交易结算：商城、代币商店、抽奖等由服务器扣费发货（规则在 js/engine/tx.js），并记账；/api/version 给出游戏版本
  social.js           社交：玩家列表、好友、名片、在线状态、切磋邀请与对战转发、观战转播
  board.js            讨论区（公开留言板），留言存在存档目录的 board.json
  admin.js            管理账号（列出账号、帮人重设密码）
  setup.sh            第一次安装用（装 Node.js、注册成开机自启的服务）
  update.sh           以后更新用
  backup.sh           备份所有存档（定时自动运行，也可手动）
  restore.sh          从备份恢复存档
  install-backup.sh   安装每 6 小时一次的自动备份（自动部署时会自动运行）
  node_modules/ws     WebSocket 库，直接放进仓库，服务器上不用再 npm install
```

**第一次安装**：在腾讯云控制台登录服务器的网页终端，粘贴运行：

```
sudo git clone --depth 1 https://github.com/Cucumber418/flame1down1 /opt/flame1down1 && sudo bash /opt/flame1down1/server/setup.sh
```

**自动部署（推荐）**：`.github/workflows/deploy.yml` 会在每次推送到 main 后，由 GitHub 把新版本上传到服务器并重启，不需要服务器去连 GitHub。一次性设置：在服务器上用 ubuntu 账号运行 `bash /opt/flame1down1/server/setup-deploy.sh`，把它打印的 `DEPLOY_HOST` 和 `DEPLOY_KEY` 填进仓库 Settings → Secrets and variables → Actions。部署记录在仓库的 Actions 页面里看。

**手动更新**：在服务器终端运行 `sudo bash /opt/flame1down1/server/update.sh`（国内连 GitHub 不稳定时可能卡住）。

80 端口被占用时（比如镜像自带了 caddy / nginx），可以换端口安装：`sudo bash /opt/flame1down1/server/setup.sh 8080`，然后在腾讯云防火墙里放行这个端口，用 `http://服务器IP:8080` 打开。

**账号与存档**：用服务器打开游戏时要先登录。存档保存在服务器的 `/opt/flame1down-data`（在仓库外面，更新代码不会影响它，网页也读不到）。密码只保存加盐哈希。
- 列出所有账号：`sudo node /opt/flame1down1/server/admin.js list`
- 有人忘记密码：`sudo node /opt/flame1down1/server/admin.js reset 账号名 新密码`
- 讨论区有不合适的留言：`sudo node /opt/flame1down1/server/admin.js board` 看最近 30 条（带编号），`sudo node /opt/flame1down1/server/admin.js board-del 编号` 删掉
- 建议在腾讯云控制台给服务器定期做快照，万一服务器出问题可以恢复存档。

**检查是否在运行**：浏览器打开 `http://服务器IP/ping`，显示 `ok` 就正常；`http://服务器IP/status` 能看到在线人数和房间数，还有服务器的 Node.js 版本（`node`）和交易结算是否正常（`tx.ok`）。

**交易由服务器结算（2026-10-24，「把游戏逻辑搬到服务器」第一批第 2 块）**：
- 物资仓储商城、竞技代币商店、先驱之塔商店、茶室商店、温泉休息室、矿石换能量、明明代币抽奖，点兑换后先发给服务器（`POST /api/tx`）。服务器在它保存的存档上检查余额、扣费、发东西，存进存档后才回复；浏览器再用服务器给的随机数和时间算一遍，两边结果一样。
- 价格、奖池、每日上限都写在 `js/engine/tx.js` 的 `TX.D`，服务器和浏览器共用这一份。改价格只改这里；加新的交易在 `OPS` 里加一项。规则里只能用 `env.now` 和 `env.rand()`，不要直接用 `Date.now()` / `Math.random()`。
- 每笔交易记在存档目录的 `ledger.log`（时间、账号、操作、余额变化），查账用：`sudo tail -n 50 /opt/flame1down-data/ledger.log`。
- 双击 `index.html` 本地打开时没有服务器，交易在本机结算，和以前一样。
- 这一步还没有挡住改档：其他获得资源的地方（任务、邮件、剧情、对战奖励等）还在浏览器里算，服务器暂时照旧接受上传的存档。等这些都搬到服务器后，上传的存档里的经验、能量、代币、道具数量会被服务器忽略。

**进账申报与钱包核对（2026-10-24，第一批第 3、4 块）**：
- `js/ui/game.js` 里所有让经验背包、能量、竞技代币、先驱代币、功勋、道具**变多**的地方，都要写成 `earn(来源, 编号, { exp, energy, tokens, twTok, merit, meritXp, items: { 道具: 数量 } })`。它先在本机加上，再记一条申报，随下一次上传存档一起发给服务器。花掉、用掉（变少）不用申报。旧写法 `giveItems` / `giveMerit` 还能用，会自动申报成来源 `misc`，新代码请用 `earn` 并写明来源。
- 服务器（`server/claims.js`）逐条检查：来源要在 `SRC` 里（1 = 一次性，同一个编号只认一次；0 = 可重复）；数值不能超过单条上限；同一条申报重复上传只算一次。认过的一次性奖励记在账号文件的 `claimed` 里，改存档改不到。新增一种来源要在 `SRC` 里加上。
- 然后核对钱包：上传存档里的每一项不能超过「服务器上一份存档 + 这次认可的申报」。
- **已正式开启（`MODE = 'enforce'`，2026-10-24）**：多出来的数值会改回去，玩家页面弹窗说明并用服务器的进度重新加载。上线前就打开、还没刷新的旧页面传不了申报，北京时间 2026-10-26 00:00 之前对它们只记录不修正（`GRACE_UNTIL`）。要临时退回只记录，把 `MODE` 改成 `'observe'`。
- 对不上的记录：记录在 `/opt/flame1down-data/wallet.log`（`sudo tail -n 30 /opt/flame1down-data/wallet.log`）；`/status` 的 `wallet` 里能看到上传次数（`uploads`）、对不上的次数（`mismatch`）和最近几条（`recent`，不含账号名；`old: true` 表示是还没刷新的旧页面传上来的，可以忽略）。
- 如果 `recent` 里出现 `old: false` 的记录，多半是有进账的地方漏了 `earn`，照着记录里的字段去找。
- 还没保护到的：奖励的具体数额仍由浏览器计算（服务器只卡上限和次数）；精灵的等级、天赋、学习力等不在核对范围内，由原来的防改档检查（`accounts.js` 的 `cheatCheck` / `dayCheck`）兜底。

**联网对战由服务器当裁判（2026-10-24，第二批第 2 块）**：
- 以前切磋、争霸赛、大乱斗由发起方的浏览器结算，现在由服务器结算：服务器用 `js/engine/pvp.js` 把双方配队变成对战用的精灵（规则和 game.js 里的 `HSACC.spec` / `balSpec` / `brawlSpec` 一致），用 `battle.js` 算每一回合，双方浏览器只提交出招、播放结果。出招不合法或超时（90 秒 + 15 秒动画）由服务器代选；认输只能发 `quit`，不能提前结束对局。争霸赛每一局的胜负由服务器记录，不再听浏览器报的。
- 浏览器连上时在 `auth` 里报 `pv: 2`（支持服务器裁判）。双方有一方是旧页面时：北京时间 2026-10-26 00:00 之前仍按旧办法由发起方结算，之后拒绝开打并提示刷新（`server/pvp.js` 的 `GRACE_UNTIL`）。

**先驱之塔由服务器结算（2026-10-24，第二批第 1 块的试点）**：
- 用服务器网址玩时，先驱之塔的对战由服务器开（`POST /api/pve`，`server/pve.js`）：服务器从存档里取出战配队、按 `js/engine/pve.js` 的规则生成这一层的对手，电脑 AI 和每一回合都在服务器上算，浏览器只提交出招、播放结果（`battle-ui.js` 的 `startStory` 传 `remote`）。打完后服务器直接把奖励（经验背包、先驱代币、死神代币）和塔的进度写进存档，浏览器照服务器给的结果（`PVE.towerApply`）更新本机存档，不再申报塔的奖励。
- 塔的进度（层数、存档点、最高层、通关次数、死神代币次数、今天的塔内奖励）只认服务器的：上传的存档里改了这些，会悄悄改回服务器的（`claims.js` 的 `twFix`）。
- 每次请求带 `seq`：网络断了重发同一个，服务器回上次的结果，不会多打一回合。对战只放在内存里，服务器重启（部署更新）后进行中的对战作废，不发奖励也不扣层数。战斗里用掉的道具：打完时存档里的数量不超过「开打时 − 用掉的」。
- 本地双击打开（没有服务器）时仍在本机结算，规则同一份。其他单人对战（剧情、野外、BOSS、挑战、茶室等）以后照这个框架逐个搬。
- 对战状态发给浏览器前用 `battleJSON(S, obj)`（battle.js）去掉精灵之间的相互引用（隐藏技能的领悟条件会记「是谁让它冰冻的」），不然转 JSON 会循环引用；联网对战（`server/pvp.js`）也用它。

**版本检查**：服务器启动时按网页、样式、脚本的内容算一个版本号（`GET /api/version`）。开着的页面每 3 分钟、以及切回页面时检查一次，发现服务器上的版本变了就弹窗提示刷新；用旧页面兑换东西时服务器会拒绝（不扣费）并提示刷新。

## 小段位

铂金到宗师（`RANKS` 下标 4~9）每个段位分成 V、IV、III、II、I 五个小段，V 最低。存档 `hs-rank-v1` 多了 `dv`（当前小段，5 = V … 1 = I）和 `bestDv`（最高段位的小段）。每个小段 3 星：3 星时 V→IV→…→I，I 段再满 3 星进下一个段位的 V；0 星输掉先降小段，I…V 都降完了才降到上一个段位的 I 段（2 星）。2026-10-14 之前就在这些段位的存档没有 `dv`，读档时 `fixRank()` 补成 I 段，星数不变。

电脑强度（`rankAI(r, stars, dv)`）：用 `rankX()` 把段位换成连续刻度（铂金 V = 4.0，铂金 I = 4.8，翡翠 V = 5.0），在相邻两个段位的参数之间插值，所以每个小段都会平滑地变强一点。显示名用 `rankFull(r, dv)`（「铂金 III」）。服务器 `server/social.js` 的 `rankOut()` 也会核对 `dv` / `bestDv`，社交列表和名片显示带小段的最高段位。

## 命中与闪避

`battle.js` 的 `accMult(n)`：n = 自己的命中等级 − 对方的闪避等级。n ≥ 0 时每级 +1/3（不变）；n < 0 时查表 `ACC_DOWN`：−1 80%、−2 66%、−3 54%、−4 43%、−5 33%、−6 25%。电脑的能力值倍率（`mult`）只乘攻防速等能力值，不影响命中。

## 王者星数

平衡排位打到王者后不再晋级，胜一局 +1 星、负一局 −1 星（0 星再输掉回宗师）。存档里 `hs-rank-v1` 的 `kingBest` 记录王者达到过的最高星数，社交的玩家列表和名片显示「王者 N 星」。

王者段位里电脑随星数变强（`js/engine/ranked.js` 的 `rankAI(r, stars)`，最多算到 `KING_CAP` = 50 星）：能力值倍率从 ×1.15 涨到 ×1.45，配招比较的方案从 12 套涨到 42 套，估分更准、更常换人躲克制，对手阵容的隐藏强度比你高一点（封顶时阵容本身约 57% 胜率）。2026-10-14 起增长用一条平滑曲线（三次埃尔米特曲线）：起点的斜率 `KING_M0` 和宗师里每星的增长一样（每星约 +0.0033 倍率），中段最快约每星 +0.008，接近 50 星时慢慢停下，不会在某一星突然卡住。

## 社交与联网切磋

主菜单「社交」（在星际探索左边），需要用服务器网址打开并登录：

- **玩家**：所有注册过的账号，显示在线 / 对战中 / 离线。点一位玩家看他的名片。
- **好友**：点「加好友」把别人加进来（单向，像关注）。对方也加了你时会显示「互相关注」。
- **我的名片**：选最多 5 只展示精灵，写最多 200 字的个人宣言。名片存在游戏存档里，同步到服务器后别人就能看到。
- **我的茶室**：「我的名片」旁边的按钮，直接去自己的茶室。
- **切磋**：对在线的玩家点「切磋」，选规模（1v1 / 3v3 / 5v5）和规则。对方会立刻弹窗，30 秒内接受或拒绝。每回合 90 秒，超时自动出招。切磋不影响经验和段位。
  - **常规模式**：双方各派出出战配队的前 N 只精灵，按背包里的练度（等级、性格、学习力、技能、纹章）对战（服务器从存档里取，不能作假）。
  - **平衡模式**：所有精灵统一 LV60，技能库全部开放（自己选 4 个，默认用竞技对战里记住的配招，选好的也会记回去），性格无修正，没有学习力和纹章。接受后先进入选人阶段，服务器当裁判：
    - **普通盲选**（1v1、3v3、5v5 都有）：双方各从自己拥有的精灵种类里选 N 只并配技能，看不到对方选了什么。
    - **竞技征召**（只有 5v5）：双方各带 8~10 种精灵（要拥有至少 8 种）→ 各禁用对方 3 种 → 从自己剩下的里选 5 只并配技能。带精灵 90 秒、禁用 60 秒、选人 150 秒，超时由服务器代选。
    - 选人阶段可以退出，对方会收到提示，这场切磋取消。
- 联网对战由发起方的浏览器结算，结果和战况发给对方播放，所以两边看到的过程一定一样。对方掉线时直接判你获胜。
- **观战**：好友正在对战时（任何对战：野外、剧情、首领、茶室、竞技对战、切磋、大乱斗），玩家列表里显示「对战中 · 对战类型」和「👁 观战」按钮，点开就是实时的对战画面（信息牌、立绘和动画、战斗记录）。只能看自己加了好友的人。对战的玩家在战斗记录标题旁能看到小眼睛「👁 N」，点开是观众名单；观众在观战窗口右上角也有同样的小眼睛，能看到还有谁在看（服务器在观众进出时发 `cast-viewers` 给对战者、`watch` op=viewers 给每个观众）。
  - **全服观战邀请**：两名玩家对战（切磋、大乱斗）时，任一方可以点对战画面里的「邀请全服观战」，所有在线船员右下角会收到邀请，之后不是好友的人也能看这场。每场每分钟最多邀请一次。
  - 原理：对战的浏览器每 0.25 秒把画面（战况快照、新的战斗记录、出招 / 受伤动画提示）发给服务器，服务器转给观众（`server/social.js` 里的 cast / watch 消息）。平衡排位里对手还没派出的精灵，观众也看不到。
- **拜访茶室**：玩家列表和名片里的「茶室」按钮，可以看对方茶室里正在训练的精灵，并用自己的出战配队挑战它们（电脑操控）。每天前 5 场茶室对战各奖励 1000 累积经验（进经验背包），赢输都算，认输不算，0 点刷新。对方要读完「陆羽茶室」支线才有茶室。
- **茶室动态与留言板**（`server/homelog.js`，前端在 `social.js` 搜「茶室信息栏」）：有人拜访（`/api/home` 时记下）、摸摸展示的精灵、打完茶室对战，都记进主人的「茶室动态」，同一位访客 30 分钟内的动作合成一条；主人在线时服务器推 `home-ev` 消息弹提示，不在线时下次登录用 `peek=1` 查有几条新的，「我的茶室」按钮上显示数字。留言板在自己和别人的茶室里都有，每条最多 200 字、每人 10 秒一条；自己的留言能删，主人能删自己茶室里的任何留言。数据存在 `DATA_DIR/homelog.json`（每个茶室最多 200 条动态、300 条留言）。

改名卡：荆门 · 物资仓储的商城里 1000 能量一张，兑换后点右上角的名字，在菜单里使用。

## 异色精灵

野外精灵表（`js/data/wild.js`）里给某种精灵写 `shiny: 0.03`，遇到的这只就有 3% 概率是异色。异色的立绘放在 `images/shiny/`，在 `js/data/assets.js` 的 `SHINY_SPRITES` 里登记（键名和 `PRE_SPRITES` 一样，最终形态用精灵 id）。抓到后精灵身上记 `shiny: true`，卡片、资料、名片、对战里都标「异色」；某个形态没有异色立绘时显示普通立绘。目前：锰怪（雷公一阶）3%；锰怪、三合一锰怪是红色异色，最终形态雷公是橙色异色，三个形态都有异色立绘。

有些精灵有两种异色：野外表里再写 `shiny2: 0.005`，遇到时先按 shiny2 判定第二种异色（存档里记 `shiny: 2`），再按 shiny 判定第一种（`shiny: true`）。第二种异色的立绘在 `SHINY_SPRITES` 里键名后加 `_2`（如 `mush_s1_2`），某个形态没有 `_2` 图时退回第一种异色图。代码里用 `shinyV()` 统一取值（2 / true / false），名片、助战、首领攻略板、联网对战都会原样传 2；服务器 `server/social.js`、`server/bossboard.js` 也保留 2。目前：玛西一系蓝色 5%、黄色 0.5%（野外表按一阶「玛西」的权重写），二阶「玛西西」和最终形态「玛西露姆」都有专属的蓝 / 黄异色立绘，一阶「玛西」暂时还没有。

`audio/library/` 放还没接入游戏的原始音乐素材（目前有 Flora3TheGreatCover、Chase、Dis-communication、GrassTalk、Memory、Saver），接入时再搬进 `audio/`、改成 `bgm_xxx.mp3` 命名、调响度，并在 `js/ui/audio.js` 的 `TRACKS` 里加一条。

**以后换曲子也要先调响度**，否则会忽大忽小：

```
ffmpeg -i 原曲.mp3 -vn -map_metadata -1 -af loudnorm=I=-16:TP=-1.5:LRA=11 -ar 44100 -b:a 128k audio/bgm_xxx.mp3
```

换了文件后，把 `js/ui/audio.js` 里的 `V = '?v=1'` 改成 `'?v=2'`，玩家刷新就能听到新曲子。

在茶室里放的是茶室主人选的「茶室音乐」（见上面「茶室商店」一节）。

顶栏邮箱旁边的「🔊 声音」可以分别开关战斗音乐、界面音乐，调音量。设置只存在这台设备的浏览器里（`hs-sound-v1`），不跟账号同步。浏览器规定点过页面之后才能出声，所以打开游戏后第一下点击之前不会有声音。

## 存档冲突误报（2026-10-12 修）

关页面时 `visibilitychange` 和 `pagehide` 连着触发：云存档先用 keepalive 把进度传上去，但页面关了收不到回复，本机的版本号没更新，下次打开就会弹「存档冲突」。现在 `cloud.js` 读档时如果服务器上的内容和本机一模一样就不算冲突（`sameData`），`game.js` 的 `markOnline()` 5 秒内也不会重复改存档。

## 存档备份

服务器上的账号和存档（`/opt/flame1down-data`）会自动备份到 `/opt/flame1down-backups`：

- **每 6 小时一次**（0、6、12、18 点左右，系统定时任务 `flame1down-backup.timer`；服务器关机错过的那次，开机后会补上）
- **每次自动部署前一次**（文件名带 `deploy`）
- 每份是一个 `saves-日期-时间-标记.tar.gz`，**保留 30 天**，更早的自动删掉

这些都由自动部署装好，不用手动设置。打开 `http://服务器IP:8080/status` 能看到 `backups`：一共有几份备份、最新一份的文件名。在服务器上可以用：

```
sudo bash /opt/flame1down1/server/backup.sh manual      # 立刻手动备份一次
sudo bash /opt/flame1down1/server/restore.sh            # 列出所有备份
sudo bash /opt/flame1down1/server/restore.sh latest     # 恢复到最近一份
sudo bash /opt/flame1down1/server/restore.sh 文件名      # 恢复到指定的那份
```

恢复前会先把当前存档再备份一次（标记 `before-restore`），原来的存档目录也会改名留着，恢复错了可以再换回来。恢复会让在线的玩家断线几秒。

注意：备份和存档在同一台服务器上，能防误删、改坏存档，防不了整台服务器出问题。需要的话可以在腾讯云控制台给服务器做快照。
